# Shoot a Bullet — BACKEND (game server)

Frontend (3D client) lives at `../Shoot-a-bullet`. Colyseus + Mongo.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, token })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable. `/health` for Legion; `/monitor` and the playground are dev-only.
- **The server holds ALL progress**: the client keeps nothing in the browser. A guest's (or a serverless session's) progress lasts the page only.
- Identity: with a `token` the server verifies it (`src/bloxity.ts` `verifyToken` -> POST `/v1/auth/game-token/verify`) and the account is `legion_<user._id>`; the name and pfp come from the verified user. Without a token a client `userId` is trusted only outside production (local dev); `guest-` ids and failed verifies are guests (never saved).
- Messages client -> server: `saveProgress` (the whole snapshot), `identify` (`{ userId, username, pfp, token }` after a sign-in/out mid-session). Server -> client (private): `progress` (the saved doc, sanitized), `noProgress` (new account, guest, or no database), `serverError` (the save could not be read: saving stays off so it is never overwritten). Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp`.
- Saved progress (`PlayerDoc`, client `game.js` `snapshot()`): `damage`, `wins`, `rebirths`, `gun` (equipped, must be owned), `owned[]` (gun ids), `ammo` (AMMO tier id), `perks[]` (permanent Store perk ids), `playTime` (s). Playtime Gifts / boosts are per visit and not saved.
- Bloxity: `src/reporter.ts` queues `rebirths` and `wins` after each accepted save and reports them every `REPORT_EVERY_MS` (`POST {BLOXITY_API_URL}/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report`, `BLOXITY_REPORT_TOKEN`; only `legion_` ids; no-op without the token). `BLOXITY_BOARDS` (constants.ts) must equal the client's `BOARDS` (config.js). `src/roomReporter.ts` feeds Open Rooms (needs `MATCHMAKER_REPORT_URL`, token, game id). SIGTERM drains: Colyseus lets rooms finish, then a last score flush and Mongo close.
- `src/constants.ts` bounds must cover the client's `src/config.js` (gun / ammo ids match `ID_PATTERN`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev) as a matrix of targets (prod; staging too when `LEGION_DEPLOY_TOKEN_STAGE` is set, with its own image tag and token; manual `target` input), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100 and a plain `= <number>;`). Needs repo var/secret `LEGION_GAME_ID` (= `shoot-a-bullet`) and secret `LEGION_DEPLOY_TOKEN`. Make the GHCR package public once after the first push.
- Leaderboard board (`src/leaderboard.ts`): top `LEADERBOARD_SIZE` saved players by peak `topWins`, `rebirths`, `topDamage` (raised with `$max` on every save, so spending Wins or a rebirth reset never lowers a score), cached `LEADERBOARD_EVERY_MS`, sent to each client as `leaderboard` { boards, ranks } after its load and on a timer. The client (`src/leaders.js`, lobby board) falls back to Bloxity `getTop` when the server sends nothing.
